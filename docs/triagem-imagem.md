Além disso, a base é uma tag mutável. O resultado anterior “zero pacotes atualizáveis” se refere à consulta daquele momento; não é garantia permanente de atualização ou ausência de CVEs.
- [`Dockerfile:17`](/Users/soria/Documents/Codex/2026-11-12/c/outputs/periferia/Dockerfile:17) copia todo o node_modules do estágio de build para o runtime. Assim, ferramentas de desenvolvimento também entram na imagem. O uso do Prisma CLI para bootstrap explica parte da necessidade atual, mas não obriga API e worker a carregar todo esse conjunto.

## Recomendações concretas para a entrega A+

1. **Fechar a associação por digest:** conservar resposta do ECR com digest, manifesto/plataforma e data, inventário de pacotes/SBOM, versão efetiva do Node e bibliotecas vinculadas. Repetir o scan após qualquer alteração. A contagem igual em duas imagens não prova identidade dos achados.
2. **Avaliar uma base mais recente sem prometer zero HIGH:** Trixie possui correções verificadas para parte dos CVEs, mas mantém os dois casos indicados na tabela. Comparar o delta de pacotes e vulnerabilidades e validar TLS RDS/Prisma, inicialização e saúde antes de adotar. Não misturar pacotes de unstable em Bookworm para reduzir uma contagem.
3. **Reduzir superfície de runtime:** separar a imagem operacional de migração da imagem de API/worker e transportar somente dependências de produção e artefatos gerados necessários. Suprimir um aviso não equivale a remover o pacote; comprovar a remoção no inventário da nova imagem.
4. **Verificar hardening efetivo:** listar capabilities, SUID/SGID, dispositivos expostos, mounts e configuração PAM. Avaliar drop de capabilities e `no-new-privileges`, compatíveis com o runtime ECS utilizado, e testar o caminho mínimo de saúde/DB/SQS. São recomendações; nenhuma mudança foi aplicada nesta triagem.
5. **Gerir os achados residuais:** para cada CVE, registrar responsável, vetor/pré-condições, evidência de aplicabilidade, mitigação, prazo/data de revisão e condição de reabertura. Tratar a inconsistência webpack/zlib como pendência do scanner até validação. Não classificar glibc/mount/PAM como inofensivos apenas porque a aplicação executa sem root.

A rubrica não define que A+ depende de uma contagem arbitrária de CVEs. O argumento defensável é demonstrar atualização, rastreabilidade, redução de superfície e tratamento documentado dos riscos remanescentes, sem alegar segurança plena ou exploração inexistente sem prova.
